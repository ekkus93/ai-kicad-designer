# Rail names kept clear of part labels (2026-11-12)

The designs were generated by `NativeSchematicEngine._compile` (brief v3 power-symbol rails) from the working tree committed with this README. They were then assessed with `NativeSchematicEngine.assess` on this Linux host (KiCad 10.0.6 via `/tmp/AppDir/AppRun`), which is not the locked qualification host.

**Problem:** in inverting_gain from `review_loop_corpus_v3_2026-11-11_qwen35_256k_run5`, the "VMINUS" text sat about 1 mm above C2's "C2 / 100n". The owner asked for the crowding to be fixed. Power-symbol clearance checked other text only for overlap.

**Change:** a power symbol's glyph and rail name must keep one grid step (1.27 mm) clear of every part's reference and value. They must also keep clear of another rail name whose symbol points a different way. Excluded:
- net labels
- power flags
- rail names drawn the same way side by side, as on a connector's adjacent pins

Field tightening keeps part text the same distance from rail names. Two broader versions were tried and dropped:
- With all text counted, J1's VPLUS was pushed up beside the "OUT" label, and the 555's RST VCC arrow pointed right at C2's "REF".
- With every rail name exempt, the 555 still read "REF → VCC".

**Results:**
- All 15 corpus designs were regenerated, and every independent check passes for all of them.
- Eight changed. `drawing_before.png` is the run5 drawing.
  - inverting_gain: VMINUS rises two grid steps from C2's top pin, so its text is a grid step above "C2 / 100n". "U1C / NE5532" moved further right. See `closeup_before.png` and `closeup_after.png`.
  - reference_555_led_flasher_v8: the RST VCC arrow points up on a stub, clear of C2's "REF". C1's REF moved left, away from J1's "Supply".
  - timer_astable: R1's VCC arrow points up, not down into R1's "10k", and the RST VCC arrow points up instead of sideways.
  - dual_buffer, dual_rail_reference, noninverting_gain, rc_to_buffer, sallen_key: only "U1C / NE5532" moved 0.635 mm up, clear of the VPLUS name.
- led_long_text, led_reverse_supply, led_series, linear_regulator, rc_highpass, rc_lowpass and timer_astable_gnd are identical to run5 apart from UUIDs.
- No model review has been run on these drawings yet.
