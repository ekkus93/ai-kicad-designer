# Rail name kept clear of an op-amp power unit's pin names (2026-11-11)

The designs were generated by `NativeSchematicEngine._compile` (brief v3 power-symbol rails) from the working tree committed with this README. They were then assessed with `NativeSchematicEngine.assess` on this Linux host (KiCad 10.0.6 via `/tmp/AppDir/AppRun`), which is not the locked qualification host.

**Problem:** in inverting_gain from `decoupling_placement_2026-11-11_run1` (and the identical run4 drawing), the VMINUS arrow pointed up from C2's top pin at (87.63, 86.36). Its "VMINUS" text sat about 1 mm right of U1C's "V−" pin name. The owner asked for the crowding to be fixed. Power-symbol clearance checked the pin-name column only for overlap.

**Change:** a power symbol's rail name must keep one grid step (1.27 mm) clear, horizontally, of a bodyless unit's pin-name column.

**Results:**
- All 15 corpus designs were regenerated, and every independent check passes for all of them.
- Only inverting_gain changed. VMINUS now rises one grid step from C2's top pin and points right, at (87.63, 85.09), mirroring VPLUS on pin 8. Its text is clear of "V−". See `closeup_before.png` and `closeup_after.png`.
- The other fourteen designs are identical to `review_loop_corpus_v3_2026-11-11_qwen35_256k_run4` apart from UUIDs.
- No model review has been run on this drawing yet.
