# Rail power symbol placed at the connector (2026-11-10)

The designs were generated by `NativeSchematicEngine._compile` (brief v3 power-symbol rails) from the working tree committed with this record. They were then assessed with `NativeSchematicEngine.assess` on this Linux host (KiCad 10.0.6 via `/tmp/AppDir/AppRun`), which is not the locked qualification host.

**Problem:** in inverting_gain, the REF ground symbol for the wired ground group (J1 pin 5, U1A +, U1B +, C1) sat sideways on C1's pin. It looked redundant next to C1's wire. It is not: C2's ground connects to the rest of REF only through a same-named symbol, so the wired group needs one too. Deleting it fails ERC, electrical equivalence and rail presentation (checked on a scratch copy). The owner asked for it to be moved to J1 pin 5.

**Changes:**
- `_place_rail_symbols` (`src/ai_kicad/pivot/power_symbols.py`): for a wire group that contains a connector pin, it first tries to place the symbol pointing the conventional way (ground down, supply up). Allowed spots are:
  - the connector pin, or
  - a grid point on the group's wire within 10.16 mm of that pin. There the wire is split so the symbol lands on a wire end.

  Near the connector, a spot is also rejected when the symbol's label form (how the protected observers read it) would overlap a part body. When no conventional spot exists near the connector, the previous preference applies, so a sideways symbol is never moved to the connector.
- `_name_nets_from_power_labels`: a power label on a wire, not just on a pin, now names the auto-named net of the pins that wire reaches. The planner's layout check needs this for a symbol placed mid-wire.
- Field text placement treats power symbols' label forms as obstacles. Without this, J1's "Supply" text moved onto the VCC symbol in the 555 designs.

**Results:** all 15 corpus designs pass every independent check. Seven changed; the other eight are identical to their last generation (`horizontal_field_text_2026-11-10_run1` or `review_loop_corpus_v3_2026-11-09_qwen35_256k_run1`) apart from UUIDs.

| dual_buffer | REF sideways on C1 | REF down from J1 pin 5's wire |
