# Reference/value text of horizontal two-pin parts placed beside the body (2026-11-10)

The designs were generated by `NativeSchematicEngine._compile` (brief v3 power-symbol rails) from the working tree committed with this record. They were then assessed with `NativeSchematicEngine.assess` on this Linux host (KiCad 10.0.6 via `/tmp/AppDir/AppRun`), which is not the locked qualification host.

**Problem:** the protected compiler centres a horizontal two-pin part's reference and value about 10 mm above it. In the accepted inverting_gain drawing of `review_loop_corpus_v3_2026-11-09_qwen35_256k_run1`:
- "R2 10k" sat above U1A's + input wire, with that wire between the text and R2.
- "R1 100k" sat just under U1A's output, closer to the op-amp than to R1.

Neither the independent checks nor the model review flagged this.

**Change:** `tighten_vertical_fields_text` (`src/ai_kicad/pivot/field_layout.py`) now also handles parts with exactly two pins on one horizontal line. Their text is centred above or below the body, reference on top, at the nearest position that:
- is closer to the body than before,
- touches no wire, body, pin, label, pin number or other field, and
- does not add an owner-association witness.

**Results:** every independent check passes for all 15 corpus designs. Six have moved text; the other nine are identical to the 2026-11-09 corpus run apart from UUIDs, so they are not repeated here.
