# Adversarial Architecture Review

Date: 2026-09-19. Disposition: **proceed with the narrowed M1 boundary experiment; do not treat the wider architecture as experimentally qualified.** This review changes the specifications, not the application. No application code, schemas, tests, scaffolding or M1 implementation was created.

## Scope and method

Reviewed all eight candidate documents for identity, validation authority, compositional layout, optimization cost, headless integration, release claims and milestone dependencies. Used concrete counterexamples against the documented contracts rather than restarting corpus discovery. Existing positive/negative evidence in the documents was sufficient; this review did not recursively inspect examples or legacy trees. `.local/` was neither inspected nor used.

Rechecked current primary KiCad sources for the selected release, power/NC semantics, CLI and API boundaries, plus the versioned Freerouting CLI. No KiCad 10, solver or router experiment was run in this review. Previously recorded KiCad 9 baseline observations remain historical evidence, not new results.

## Stress-case coverage

| Case attacked | Result and remaining proof |
|---|---|
| Op-amp feedback and multi-stage analog | Ordered feedback edges and overlapping constraints now represent shared networks; M2 must show a novel composition with separate package power unit and no per-fixture coordinates. Negative-feedback polarity/stability remains an operating assertion requiring evidence. |
| Split supplies, references and virtual grounds | Distinct nets are preserved; heterogeneous rails need individual envelopes, and a virtual reference is not an ideal supply. Test equal-looking names with distinct scopes and negative-rail/rail-to-rail decoupling. |
| Switching regulators/high-current loops | Mode-specific ordered paths, switch-copper extent and actual return paths are separate from compact placement. Parallel copper/planes/internal package paths can make a loop metric unsupported; no false numeric certificate. |
| Mixed signal | Classification does not imply split grounds or separated planes. One package may serve analog/digital blocks; actual return continuity and operating analysis remain release obligations. |
| Multi-unit/hidden units/NC | Inventory is physical, drawings are occurrences; actual NC markers and all units are checked. M2 must qualify common/stacked/hidden pins before advertising support. |
| Large MCU | Pin alternates are explicit locked selections; layout cannot invent a new pin grouping/split symbol. Custom asset authoring is separate and reviewed. |
| Buses/repeated channels/hierarchy | Scalar nets remain authoritative. Per-endpoint directions and correspondence guide presentation; separate expanded sheet files avoid premature shared-definition complexity. Shared-file instances require an explicit later capability gate. |
| Connectors/off-board interfaces | Contact roles and mating evidence are explicit; singleton contacts need a purpose. Externally fixed PCB placement does not dictate schematic position or collapse mixed interfaces into one signal-flow direction. |
| USB/differential paths | Segment identities survive series/ESD/common-mode networks. Full channel skew/length needs explicit paths/component contributions; ordinary low-speed routing support cannot imply USB signal-integrity qualification. |
| Clocks/crystals/termination | Driven clocks and passive oscillators have separate relationships. Source/load termination retains endpoint identity and post-route stub/path ordering checks. |
| Custom/third-party assets | Complete resolved occurrence inventories, inheritance hashes, physical maps and provenance remain mandatory. Missing exposed contacts or ambiguous numbering require an asset correction rather than inferred placeholders. |
| Fixed mechanics versus schematic organization | One physical package/pose may correspond to units across sheets. Physical clusters add overlapping constraints, never extra package instances; no schematic-to-PCB coordinate dependency is introduced. |

## Concerns rejected or deliberately retained

- **Do not replace rich IR with a netlist.** Identity, scope, relationships and physical obligations are necessary. The simplification is implementing a strict profile first, not deleting future semantic ownership.
- **Do not discard CP-SAT entirely.** Discrete legal poses and conflicting constraints are reasonable uses. Requiring it at every layer was the avoidable commitment.
- **Do not adopt Graphviz as the schematic engine.** It does not resolve the pin/feedback/label semantics under attack. Construction and semantic routing remain the simpler first experiment.
- **Keep electrical equivalence hard and independent of geometry.** ERC, annotations and intended metadata cannot replace observed connectivity. No evidence justified weakening this decision.
- **Keep PCB coordinates independent.** Shared relationships legitimately produce different schematic and physical organizations.
- **Keep KiCad 10.0.6 as the first qualification target.** The official release exists. The issue is unproven adapter behavior, not a reason to substitute the locally installed 9.0.9 silently. [Release source](https://www.kicad.org/blog/2026/08/KiCad-10.0.6-Release/)
- **Keep the narrow SWIG bridge conditional.** Its planned removal is real, but it is outside M1 and isolated to DSN/SES. KiCad 9/10 IPC requires the GUI; do not make the server depend on it. Recheck stable alternatives before M4. [Binding policy](https://dev-docs.kicad.org/en/apis-and-binding/pcbnew/), [IPC boundary](https://dev-docs.kicad.org/en/apis-and-binding/ipc-api/for-addon-developers/)
- **Keep router repeatability as a gate.** The product explicitly promises deterministic downstream processing. Caching one lucky route does not satisfy that. Failure should preserve placement-only value while blocking routed-release claims.
- **Keep semantic/visual review beyond metrics.** Lexicographic objectives are still gameable; no scoring formula replaces independent engineering trace tasks. M1's single review is deliberately narrower than later quality qualification.
- **Keep licensing notices and separation.** This review does not grant a source-port permission or make a legal compatibility claim.

## Unresolved experiments, ordered by risk

1. **M1a: actual artifact observation.** Can the observer derive every real pin and its net state from generated files plus real KiCad output, and reject a detached branch while intent metadata stays unchanged? If not, stop before framework expansion.
2. **M1b: intentional NC and representation repeatability.** Can a missing NC marker, wrong actual pin number and stale report all fail independently? Do clean builds reproduce generated bytes and normalized observed/rendered content? No full image pipeline is needed to answer this.
3. **Early M2 identity checkpoint.** Multi-unit, power/common/stacked pins, split supplies and references must survive actual exports; resurrect the historical NE5532 negative here. Unsupported cases are explicit capability limits, not silent passes.
4. **M2 composition and optimizer ablation.** Compare constructive layout with local CP-SAT on overlapping analog/support networks and unseen symbol dimensions. Retain complexity only for measured readability/feasibility benefit under the same budget.
5. **M3 scope and scale.** Expanded repeated children, equal local names, ordered bus members and a large MCU must remain distinguishable and readable. Do not infer shared-file support from expanded-file success.
6. **M4 bridge/router matrix before broad placement.** Hand-placed fixtures must prove projection, preserved geometry, post-fill correctness and repeated copper. Establish what zones and protected tracks actually become in DSN/SES. Freerouting's documented CLI is an invocation contract, not proof of those properties. [Versioned CLI](https://raw.githubusercontent.com/freerouting/freerouting/v2.4.1/docs/command_line_arguments.md)
7. **M5 onward: actual physical/manufacturing evidence.** Resolve ambiguous current-loop/SI measurements through qualified analysis, then reconcile exported CAM/BOM/positions and fabricated behavior with exact artifact hashes.

The highest-risk M1 hypothesis is independence of observation, not schematic optimization. A beautiful divider with an observer that trusts generated metadata is a failed milestone. A narrow, independently verified divider with an honest unsupported-capability boundary is a successful starting point.

## Review completion and limitations

All material corrections above are in the governing specifications. The consistency pass also reconciled M1 power-asset/image requirements, function-owned net scopes for split packages, and the BOM rule allowing an explicitly approved generic procurement specification instead of requiring an MPN in every case. M1 has a concrete input, supported subset, function boundaries, command, output evidence, error policy and falsification cases; an implementation agent need not redesign the system before starting M1a. Full later capability schemas and algorithm details are deliberately not an M1 prerequisite.

Documentation validation checks links/anchors, Markdown structure and the representative JSON's identity/membership consistency. These checks do not prove KiCad, solver, router or engineering performance. The experiments remain explicit milestone gates. Stop at these documents; no implementation is authorized by this review task.
