# Legacy Reuse Decisions

Status: evidence-based disposition, 2026-09-19. The curated [legacy snapshot](../research/legacy_openclaw/README.md) is prior art, not the governing architecture. Decisions below concern the files actually present. Omitted Graphviz/router/web/refinement implementations were not inspected and are not presumed correct or available.

## 1. Policy and license boundary

The repository root contains an Apache-2.0 license; the retained snapshot contains GPL-3.0 license text and declares GPL-3.0-or-later in its package metadata. Preserve those notices and the separate third-party licenses of the examples. Do not assume legacy code can simply be copied and relabeled as new core code.

**Decision:** the new core has its own implementation and package; no runtime imports from `research/legacy_openclaw/`. `reuse/port` below means retained fixture/reference-harness use or porting a test contract, as specified in the row. It does not authorize a production source-code port across the existing license boundary. Any future literal source port needs an explicit compatible licensing decision and preserved notices. This design does not change the repository's license.

Reusing an algorithmic idea or test requirement is different from depending on the old data model. No claim of a legally “clean-room” process is made: the legacy sources were read during this investigation.

## 3. Concrete lessons retained

The old membership validator records every assignment before detecting duplicates. Retain that traceability: a new error should identify both conflicting net memberships, not merely say “invalid pin.” Preserve tests that distinguish a missing required net from an equally named net with different terminals.

The electrical-equivalence code deliberately separates geometry from fingerprints. Keep that principle, but strengthen the identity model. A physical terminal is not `(ref, pin, optional drawing unit)`, and a net is not identified by stripping its hierarchy prefix. Explicit package/instance maps remove the need to guess whether `U1A` was generated from `U1`.

The low-level symbol work shows why libraries are part of the trusted input: pin endpoints, unit identity and inherited definitions affect both layout and connectivity. A deterministic but incomplete symbol resolver can still generate the wrong circuit. Pin inventories and geometry must be qualified against real KiCad behavior.

The current NE5532 fixture makes the distinction measurable. A fresh KiCad 9.0.9 export during this task returned only `C1.1` on `VPLUS15`, while the fixture IR requires `C1.1`, `C3.1`, `J3.1` and `U1.8`. KiCad also emitted an annotation warning while returning zero. Hidden markers and favorable spread metrics cannot overrule that observation.

## 4. Limits of the snapshot and migration strategy

This is a curated partial tree, not a ready dependency. For example, `_schematic_metrics_wires.py` and `corpus/layout_features.py` import `kicad_pcb.lint`, which is absent from the snapshot; package entry points refer to omitted `kicad_pcb_web` modules. No full legacy test-suite pass is claimed. Avoid restoring the old application merely to make every historical helper importable.

M1 implements the new interfaces directly and preserves the original research tree. Historical circuits enter through explicit fixture migrations: retain original JSON, map stable IDs/terminals, resolve symbols, add reviewed roles/domains and record all differences. Unknown engineering intent stays unresolved. A migration must not quietly delete extra components to align a bad and a baseline example.

Before adopting any legacy behavior, require a minimal failure reproducer, comparison with current KiCad behavior, the new invariant it serves and tests under the new identity model. Useful prior art earns its place through evidence; the amount of old working code is not a reason to keep its architecture.

## 5. Review clarification: concepts are not source ports

The adversarial review preserves the licensing boundary. “Port a test contract” means author a new test from a stated behavior; it does not authorize copying GPL test code, helper implementations, comments or fixture-generating code into Apache implementation directories. Retain original GPL material with notices under research and reference it explicitly when used as historical evidence. New implementation code must be independently authored; do not translate or lightly refactor a legacy function and treat that as a new license.

Fixtures and third-party symbols have their own provenance/licensing requirements. Do not assume generated output or research location automatically removes restrictions, and do not bundle legacy code into production distributions. Before literal reuse, record the specific source/license and obtain a compatible licensing decision; absent that decision, reimplement the required behavior. Calling KiCad/Freerouting through process/file boundaries keeps their implementation out of the Apache core; distributing those binaries still requires their notices and applicable distribution obligations. This review makes no legal compatibility certification.

M1 no longer needs the multi-unit NE5532 historical regression to implement its narrow observer. A new divider branch-removal mutation retires that risk first; the historical fixture returns at M2 when the new adapter supports its actual constructs. No legacy source files needed reinspection for this correction: the already documented subsystem evidence was sufficient.
